# Unity CLI 사용 피드백 (2026-09-20)

게임 저장소 ProjectMozzi2 에서 하루 동안 Unity CLI(`unity command …`)로
재료 아이콘 배선 · TMP 외곽선 · WebGL 빌드 줄이기를 하며 본 것이다.
Unity CLI 를 맡은 툴이 따로 없어 여기 적는다. 자리가 정해지면 그쪽으로 옮긴다.

## 결론

- **가장 크게 덴 것은 「조용히 성공」이다.** Play 가 꺼져 있어도 · 셰이더 키워드가 꺼져 있어도
  명령은 성공을 돌려준다. 실패가 안 보이니 엉뚱한 데를 몇십 분 팠다.
- **자산 수정은 YAML 손편집보다 `eval_file` 의 `SerializedObject` 가 훨씬 빠르다.** 예상 150분짜리가 25분에 끝났다.
- 컴파일 오류 안내와 `editor_status`·`console` 되돌이는 빠르고 정확했다.

## 막힌 것

| # | 무엇 | 어떻게 됐나 | 바라는 것 |
| --- | --- | --- | --- |
| 1 | `eval` 이 Play 가 꺼져 있어도 성공을 돌려준다 | Play 가 혼자 멈춘 줄 모르고 임시 오브젝트를 찍었더니 **Edit 모드 씬에 그대로 남았다** | 상태를 바꾸는 `eval` 은 playMode 를 같이 찍거나, 「지금 Edit 모드다」를 한 줄 경고한다 |
| 2 | `eval` 에러가 `--format json` 전체를 봐야 보인다 | `grep '"result"'` 로 거르면 실패가 **빈 출력**으로 조용히 나온다 | 사람이 읽는 기본 출력에 오류를 먼저 찍는다 |
| 3 | `Type.GetType("…, Assembly-CSharp")` 이 안 먹는다 | 프로젝트 코드가 asmdef 안에 있어 어셈블리 이름이 다르다. 타입을 직접 써서 풀었다 | 문서에 「asmdef 를 쓰면 `Assembly-CSharp` 가 아니다」 한 줄 |
| 4 | `InGameHub` 의 정적 표가 `eval` 에서 비어 보인다 | Play 중인데도 `n=0` 이다. **까닭 못 밝힘.** Manager 가 MonoBehaviour 가 아니라 CLI 로 게임 상태를 만지기 번거롭다 | `eval` 이 어느 도메인·어느 어셈블리 문맥에서 도는지 안내 |
| 5 | TMP `outlineWidth` 만 넣으면 아무 일도 안 일어난다 | `TextMeshPro/Mobile/Distance Field` 는 `OUTLINE_ON` 이 shader_feature 라 **키워드를 켜야** 보인다. `GetFloat("_OutlineWidth")` 는 값이 멀쩡히 들어 있어 머티리얼만 보면 원인을 못 찾는다. 결국 화면 캡처로 알았다 | 머티리얼 속성 읽기에 **켜진 셰이더 키워드**를 같이 찍는다 |
| 6 | `build_status` 가 `build` 명령으로 건 빌드만 본다 | `BuildPipeline.BuildPlayer` 를 `eval` 로 부르면 안 잡혀 **Editor.log 를 직접 읽었다** | eval 로 건 빌드도 잡거나, 「이 빌드는 추적 안 된다」를 알린다 |
| 7 | Bash 도구에서 전경 `sleep` 이 막혔다 | recompile · play 기다리기를 PowerShell `Start-Sleep` 루프로 돌려야 했다 | 「끝날 때까지 기다린다」 옵션(`--wait`)이 있으면 폴링이 필요 없다 |

## 헷갈린 것

| # | 무엇 | 자세히 | 바라는 것 |
| --- | --- | --- | --- |
| 1 | `console --level Error` 의 시각이 UTC 다 | 내 판에서 난 오류인지 가리려고 `editor_status` 의 `lastHeartbeat` 와 맞춰 봐야 했다 | 시각 기준 `--since` 옵션, 또는 로컬 시각 표시 |
| 2 | `capture_game_view --save_path` 가 `Assets/` 아래만 받는다 | `Assets/Temp/` 폴더와 `.meta` 를 **조용히 만든다.** 저장소에 남을 뻔했다 | 프로젝트 밖 경로를 받거나, 만든 폴더를 알린다 |
| 3 | URP 6 의 `m_StripUnusedPostProcessingVariants` 가 세 곳에 있다 | 레거시 최상위 · `m_URPShaderStrippingSetting` · `m_Settings` 의 SerializeReference RID 블록. **하나만 고치면 안 먹는다** | 자산 수정 안내에 「같은 이름 필드가 여럿일 수 있다」 한 줄 |

## 잘 된 것

| 무엇 | 왜 좋았나 |
| --- | --- |
| `eval` 의 컴파일 오류 메시지 | `using` 을 못 쓰는데도 네임스페이스가 틀렸을 때 어디가 틀렸는지 정확해 바로 고쳤다 |
| `console --level Error` + `editor_status` | 컴파일 상태를 바로 봐서 되돌이가 빨랐다 |
| `eval_file` + `--detach` | 5분짜리 WebGL 빌드를 끊김 없이 돌렸다 |
| `eval_file` + `SerializedObject`·`GetIterator()` | 같은 이름 필드 세 곳을 한 번에 잡았다. `AssetDatabase.MoveAsset` 과 함께 쓰니 **예상 150분 → 실제 25분** |
| `capture_game_view` 의 Edit 모드 안내문 | `--source screen` 은 Play 에서만 된다는 것을 친절히 알려 줘 바로 알았다 |

## 바라는 것

- `capture_game_view` 에 **crop 인자**. 픽셀아트 28px 아이콘을 눈으로 보려고 PowerShell `System.Drawing` 으로 직접 잘랐다.
- 상태를 바꾸는 명령 앞에 playMode 를 자동으로 확인하는 안전장치(또는 `--require-play`).
