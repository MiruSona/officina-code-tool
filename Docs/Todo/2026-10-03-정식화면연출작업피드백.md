# 정식 화면 · 합성 연출 작업 피드백 (2026-10-03)

게임 저장소 ProjectMozzi2 에서 UI 프리팹 둘을 배경 그림 위 배치로 다시 놓고,
LitMotion 으로 화면 연출을 붙이며 본 것이다.

## 결론

- **프리팹 배치는 「손질기 스크립트 하나 + 자리 상수」 로 끝까지 된다.** Editor 정적 클래스가 `LoadPrefabContents` 로 열어
  자식을 옮기고 `SaveAsPrefabAsset` 으로 닫는다. `eval` 로 한 줄에 부르고, 몇 번 돌려도 같은 결과가 되게 쓰면 자리 고치기가 빠르다.
- **1초짜리 연출의 중간 프레임은 「멈춤 + 한 프레임씩」 으로 찍는다.** 시작 버튼을 누르는 `eval` 안에서 바로
  `EditorApplication.isPaused = true` 를 걸고 `EditorApplication.Step()` 을 나눠 부르며 `capture_game_view` 를 찍었다.
- **한 프레임이 몇 초인지는 믿지 못했다.** `Step()` 한 번을 `eval` 한 번으로 불렀는데 연출이 예상보다 빨리 나갔다
  (`eval` 사이에 프레임이 더 도는 듯하다). 순서는 다 봤지만 「0.25초 지점」 같은 정확한 때는 못 골랐다.

## 잘 된 것

- 코딩컨벤션의 「배선은 코드에 · 모양은 프리팹에」 가 그대로 맞았다. 스프라이트는 코드가 키로 끼우고 프리팹에는 빈 Image 자리만 둬서
  그림 파일이 바뀌어도 프리팹 diff 가 안 생긴다.
- 연출 상태를 enum 하나(None · Idle · Merging · Running · Done)로 두니 「같은 칸이 이미 도는 중이면 다시 걸지 않는다」 가 한 줄 비교로 끝났다.
- 모션 핸들을 `CompositeMotionHandle` 하나에 모으고 화면 닫기 · 칸 바꾸기에서 `Cancel` 하니 풀로 돌아간 화면을 건드리는 오류가 없었다.
- `console_status` 의 `consoleErrors` 한 줄로 단계마다 오류 0 을 확인했다.

## 막힌 것

| # | 무엇 | 어떻게 됐나 | 바라는 것 |
| --- | --- | --- | --- |
| 1 | `EditorApplication.Step()` 을 `eval` 로 부르면 프레임 수가 안 맞는다 | 한 `eval` 안에서 여러 번 불러도 한 프레임만 가고, `eval` 을 여러 번 부르면 예상보다 많이 간다 | 「N 프레임 가서 찍기」 틀을 가이드에 둔다. 연출 쪽에 시험용 시각 넣기(스케줄러를 손으로 돌리기)도 길이다 |
| 2 | 옛 손질기 스크립트가 쌓인다 | 배치를 바꾸니 옛 손질기 셋이 「돌리면 깨지는 것」 이 됐다. 지우기는 사용자 확인이 필요해 남겼다 | 컨벤션에 「한 번 쓰는 손질기는 배치가 바뀌면 지우거나 새 것이 덮는다」 를 적는다 |
| 3 | 실시간 연출은 배속으로 늦춰 볼 수 없다 | UI 연출을 `unscaledDeltaTime` 으로 돌리니 `TimeScale` 로 늦춰 찍기가 안 됐다 | 연출 스케줄러에 시험용 배율을 하나 둘지 정한다 |
| 4 | 오프라인 팝업이 첫 화면 캡처를 가린다 | Play 직후 「돌아왔어요」 가 떠서 첫 장을 버렸다 | 캡처 틀 첫 줄에 「팝업 닫기」 를 넣는다 |
