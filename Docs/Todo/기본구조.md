## 기본 구조 정리

### 1. 최상위 : ~Master

- 네이밍에 ~Master를 붙인다
- 모든 Manager들의 new, Init, Process, FixedProcess, LateProcess, Dispose 관리
- 모든 Manager들을 new해서 관리한다
- 씬 로드 ~ 종료 까지만 존재
- 이 게임오브젝트는 1개만 존재하며, 이 게임오브젝트가 파괴될 때(씬 종료 시) 관리중인 모든 Manager들도 같이 정리(Dispose)한다

### 2. 상위1 : ~Manager / ~Hub

- ~Manager
  - 네이밍에 ~Manager를 붙인다
  - 모든 Manager는 두개의 인터페이스를 상속한다
    - IManager
      - Init, Process, FixedProcess, LateProcess, Dispose 가 있다
      - Init : 공용 초기화
      - Process(float deltaTime) : MonoBehaviour의 Update
      - FixedProcess(float deltaTime) : MonoBehaviour의 FixedUpdate
      - LateProcess(float deltaTime) : MonoBehaviour의 LateUpdate
      - Dispose : 메모리 정리, 관리중인 하위 오브젝트들 정리
    - I~Hub
      - ~Hub에 연결한다
      - Manager마다 외부 참조가 필요한 함수들만 작성한다
      - I~Hub는 ~Hub에서 관리한다
      - ~Hub는 Singleton을 최소화 하기 위한 조치이다
- ~Hub
  - 네이밍에 ~Hub를 붙인다
  - Manager들의 I~Hub들을 전부 관리한다
  - static 클래스이며, 내부에서 I~Hub를 캐싱해둔다
  - Manager를 참조하고싶으면 이 ~Hub를 통해서 접근한다
    - 예시) ResourceHub.Get<IAddressableHub>().Find("A.prefab")
  - ~Hub는 Manager들의 상위 범주로 묶는다
  - 만약 특정 시스템에서만 사용할 경우 그 시스템용 ~Hub 하나만 만든다
    - 예시) 인게임용 : InGameHub / 아웃게임용 : OutGameHub

### 3. 중위 : ~Object

- 네이밍에 ~Object를 붙인다
- Manager가 관리하는 객체들
- 인게임에서 실제로 움직이는 NPC, Player, Monster, Item 등이 여기에 해당한다
- State가 있을 수 있다
- Manager에 의해 생성되고 Manager에 의해 제거된다

### 4. 하위 : ~Agent / ~Util

- 둘다 Manager 또는 Object 하위에 붙는다
- ~Agent
  - 네이밍에 ~Agent를 붙인다
  - Manager 또는 Object의 책임이 무거워 지거나 기능이 많아질 경우 책임/기능 분리를 위해 ~Agent 클래스를 만들어 분리한다
  - 예시) ViewAgent를 Object하위에 : Object의 외형, Sprite, Anim등을 관리
- ~Util
  - 네이밍에 ~Util을 붙인다
  - Manager 또는 Object 등에서 특정 반복되는 기능들을 공유 또는 정리할 때 ~Util을 만들어서 관리한다
  - 예시) Sprite의 색값을 바꾸는 기능들을 묶어서 SpriteColorUtil 로 만듬
