# 반복 03 버그 수정 묶음 — 코딩 컨벤션 피드백

> 2026-10-03 · ProjectMozzi2 의 반복 03 코드 갈래(흰찹쌀이 색 · 정식 화면 알파 · 세이브 셋 · 합성소 입구 누름)를 하며 느낀 것.

## 잘 된 것

- **2-9(한 번 쓰는 코드는 함수로 안 뺀다)** 가 판단을 빨리 끝내 줬다. 「종 → 몸 색」은 다섯 자리에서 불려서 함수 하나로 모았고, 입구 누름 배선은 한 번뿐이라 그 자리에 뒀다. 기준이 「두 번 이상」으로 숫자라 망설일 일이 없었다.
- **2-6(주석 최대 2줄 · 히스토리 금지)** 덕에 세이브 쪽 주석을 「왜 막나」 한두 줄로만 썼다. 고친 날짜·까닭을 주석에 적고 싶은 마음이 들었는데 규칙이 막아 줬다.
- **2-5(`? :` · `??` 안 쓰기)** 는 기존 코드가 전부 지키고 있어서 새 코드도 같은 꼴로 맞추기 쉬웠다.

## 헷갈린 것

- **2-9 와 「같은 일을 하는 짧은 함수 둘」** : 초를 올림하는 한 줄(`(int)Math.Ceiling(seconds)`)이 표시 글자 만들기와 「초가 바뀌었나」 비교 두 자리에서 쓰여 `CeilSec` 로 뺐다. 두 번이니 규칙에는 맞지만, **한 줄짜리를 함수로 빼는 것이 2-3(평범한 세 줄)보다 나은지**는 문서에 기준이 없다. 「한 줄이어도 두 자리가 같은 값을 내야 하면 뺀다」 같은 한 줄이 있으면 좋겠다.
- **예외를 넓게 잡는 자리** : `File.Replace` 가 플랫폼에 따라 무엇을 던지는지 몰라 `catch (Exception)` 으로 잡고 덮어 베끼기로 물러났다. 컨벤션에 **「넓게 잡아도 되는 때」** 가 없어 리뷰에서 걸릴지 알 수 없다. 기존 SaveManager 가 이미 같은 꼴이라 따랐다.
- **이벤트 struct 를 어디에 두나** : `AppBackgroundEvent` 를 알리는 쪽(Core)에 둘지 이벤트 폴더(Events)에 둘지 문서에 없다. 기존 이벤트가 전부 「알리는 Manager 옆」에 있어서 그 관례를 따랐다.

## 막힌 것

- 없다. 다만 **긴 편집 스크립트를 셸 heredoc 으로 넘기다 따옴표가 깨져** 한 번 다시 했다 (컨벤션이 아니라 작업 환경 문제 — 긴 스크립트는 파일로 쓴 뒤 돌린다).
