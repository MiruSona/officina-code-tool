# 기본 구조 1차 설계

> 원문 : `Todo/기본구조.md` (4층)
> 이 문서 : 원문에서 비어 있던 **씬을 넘어가는 것 · 생명주기 · Update 진입점**을 채운 1차 설계
> 안 정한 것은 아래 6장에 모아뒀다.

## 1. 결론

**층이 4개에서 7개로 늘었다.** 원문의 4층은 그대로 있고, 그 위에 **앱 전체를 사는 층**이 붙었다.

| 층 | 정체 | 사는 기간 | 만드는 이 |
| --- | --- | --- | --- |
| `GameMaster` | **static** | 앱 전체 | 자동 부팅 |
| `GameRunner` | **Mono** (DontDestroyOnLoad) | 앱 전체 | `GameMaster` |
| `~Service` | 순수 C# | 앱 전체 | `GameMaster` |
| `~Master` | **Mono** | 씬 하나 | `GameMaster` |
| `~Manager` | 순수 C# | 씬 하나 | `~Master` |
| `~Object` | **Mono** | Manager 가 정함 | `~Manager` |
| `~Agent` / `~Util` | 순수 C# | 붙은 놈 따라감 | Manager · Object |

**Mono 는 셋뿐이다** — `GameRunner`, `~Master`, `~Object`. 나머지는 전부 순수 C# 이다.

**꺼내 쓰는 길은 `~Hub` 하나뿐이다.** 전역이든 씬이든 똑같이 Hub 로 꺼낸다.

## 2. 이렇게 정한 이유

### 2-1. 매 프레임 도는 곳은 딱 한 군데

`GameRunner` 의 `Update` 하나가 유일한 진입점이다. `~Master` 는 Mono 지만 **`Update` 를 쓰지 않는다.**

Mono 가 여러 개면 그들 사이 순서를 **Unity 가 정하고 우리는 모른다.** 그러면 `InputService` 가 읽은 입력을 `PlayerManager` 가 다음 프레임에 받는 식으로 한 박자씩 밀린다. 고치려면 Project Settings 의 Script Execution Order 를 만져야 하는데, 그건 **코드 밖에 숨는 설정**이라 「인스펙터에 배선을 숨기지 않는다」 규칙(스튜디오 저장소 공용 규칙 10번)과 부딪힌다.

진입점이 하나면 순서가 코드에 그대로 적히고, **deltaTime 을 만드는 자리도 하나**가 된다. 슬로우모션·일시정지가 그 한 줄로 끝난다.

### 2-2. 씬을 넘어가는 것은 `~Service` 로 따로 뺀다

`~Manager` 는 "`~Master` 가 new 해서 굴리는 것" 이다. 저장·설정·리소스·테이블처럼 **아무도 new 해주지 않고 앱 내내 사는 것**은 성격이 달라서 이름을 갈랐다.

`GameMaster` 가 이걸 직접 들고 있지 않는다. 총괄이 상태까지 떠안으면 아무거나 들어오는 통이 된다.

### 2-3. `~Master` 가 Mono 인 이유

씬에 속한 GameObject 라 **씬이 사라지면 Unity 가 알아서 죽인다.** `OnDestroy` 에서 Manager Dispose 와 Hub 정리가 저절로 불린다. 공짜로 주는 안전장치다.

## 3. 한 프레임

```csharp
// GameRunner (Mono, DontDestroyOnLoad, 게임 통틀어 하나)
void Update()
{
    float dt = Time.deltaTime * GameMaster.TimeScale;   // 조절은 여기서 한 번만
    서비스들.Process(dt);        // 등록 순
    마스터들.Process(dt);        // 등록 순
}
void FixedUpdate() { ... FixedProcess(Time.fixedDeltaTime) ... }   // 물리 동기 — TimeScale 을 안 건다
void LateUpdate()  { ... LateProcess ...  }
```

```
GameRunner.Update
  → ~Service 들 (등록 순)
  → ~Master 들 (등록 순)
       → ~Manager 들 (등록 순)
            → ~Object 들
```

- **`GameMaster.TimeScale` 은 `Process`·`LateProcess` 에만 걸린다.** `FixedProcess` 는 물리와 같은 시간을 써야 해서 `Time.fixedDeltaTime` 을 그대로 넘긴다. 물리까지 함께 느리게 하려면 `Time.timeScale` 을 쓴다.
- `GameRunner` 는 **목록과 순서만 안다.** 씬을 불러오고 `~Master` 를 만드는 건 `GameMaster` 일이다.
- `~Master` 가 하나도 없는 프레임(씬 전환 중)은 Service 만 돌고 지나간다. **오류가 아니라 정상이다.**
- Master 가 여러 개일 때(인게임 씬 + UI 씬을 겹쳐 열 때) 순서는 **등록 순서 그대로**. 모자라면 그때 우선순위를 붙인다.

## 4. 생명주기

```
[부팅]      GameMaster.Init          자동으로 한 번 (RuntimeInitializeOnLoadMethod)
              → 이전 static 상태부터 지운다   ← Domain Reload 를 끈 에디터 대응
              → GameRunner 를 코드로 만든다 (new GameObject + DontDestroyOnLoad)
              → ~Service 들을 만들어 Hub 에 등록
[씬 로드]   GameMaster 가 ~Master 를 코드로 만들어 씬에 붙인다
              → ~Master 가 자기 Manager 들을 new → Init → Hub 에 등록
              → ~Master 가 GameRunner 에 자기를 등록
[씬 종료]   Unity 가 ~Master 를 파괴 → OnDestroy
              → GameRunner 에서 자기를 뺀다      ← 스스로 빠져나간다
              → 자기가 넣은 것만 Hub 에서 뺀다
              → Manager 들을 Dispose
```

- **등록은 남이 해줘도 해제는 자기가 한다.** `OnDestroy` 는 어떤 경로로 죽어도(씬 전환, 에디터 정지) 반드시 불린다. `GameMaster` 가 빼주는 방식은 예외 경로에서 샌다.
- **`~Master` 도 씬에 미리 놓지 않는다.** 씬을 다 불러온 뒤 코드로 만들어 붙인다. 그래야 어느 씬에 어느 Master 가 붙는지 코드에 남는다.
- **Hub 는 Master 와 생명주기를 같이 간다.** Master 가 죽을 때 자기가 넣은 것만 뺀다. 전역 Service 는 앱 끝까지 남는다.

## 5. 매 프레임 도는 전역이 생기면

`~Service` 는 전부 순수 C# 이다. 매 프레임이 필요한 것만 인터페이스로 표시한다.

```csharp
interface IServiceProcess { void Process(float deltaTime); }
```

`GameRunner` 가 이걸 단 Service 만 등록 순으로 돌린다. **Mono 를 새로 만들지 않는다.**

지금 잡아둔 Service(저장·설정·리소스·테이블·사운드) 중에 매 프레임 필요한 건 **하나도 없다.** 사운드 페이드도 async 로 처리하면 된다. 그래서 시작할 때 `IServiceProcess` 를 단 Service 는 0개다.

> Mono 인지 여부를 **클래스 이름에 박지 않는다.** 그건 구현 방식이라 바뀌기 쉬운데, 이름이 바뀌면 부르던 곳이 전부 따라 바뀐다.

## 6. 아직 안 정한 것

- **Init / Process 순서를 뭐로 정하나** — 등록 순서로 하면 되는지, 의존 관계를 코드에 적을 방법이 필요한지
- **`~Agent` 와 `~Util` 을 뭘로 가르나** — "상태를 갖고 있으면 Agent, 없으면 Util" 같은 눈에 보이는 기준
- **`Hub.Get<T>()` 가 못 찾았을 때** — null 인지 예외인지. 조용히 넘어가면 원인 찾기가 아주 길어진다
- **돌리는 중에 목록이 바뀌는 것** — `Process` 도중 씬이 뜨거나 Master 가 죽으면 그 자리에서 예외. 복사본 순회 / 프레임 끝으로 미루기 중 택
- **Manager 하나가 두 Hub 에 걸칠 때**
- **`~Object` 를 만드는 경로** — Object 가 Mono 라 프리팹을 불러와야 하고, 그러면 Addressable · 풀링과 바로 엮인다
- **Manager 끼리 알리는 길** — Hub 는 "가서 꺼내오는" 통로다. "죽었다", "씬 다 떴다" 같은 **알림**을 보내는 길은 아직 없다
