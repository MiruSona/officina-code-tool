## 1. 템플릿 파일 목록

### 1-1. 모양

```
CodeTool/Template/                       ← 이 아래가 그대로 Assets/ 밑에 놓인다
├─ Default.globalconfig                  → Assets/Default.globalconfig
└─ _Project/Scripts/                     → Assets/_Project/Scripts/
   ├─ Officina.Runtime.asmdef
   ├─ Core/  Hub/  Events/  Resource/  Sample/
   └─ Editor/
      └─ Officina.Editor.asmdef
```

**원본 폴더를 목적지별로 가르지 않는다.** 조사 2-1절은 목적지가 셋이라 `RepoRoot/` · `UnityRoot/` · `Assets/` 로 가르자고 했는데,
범위가 `Assets/` 한 군데로 줄어서 **가를 이유가 없어졌다.** 가르지 않으면 「원본 상대경로 = 목적지 상대경로」라
스크립트의 경로 감옥 검사가 한 줄로 끝난다.

### 1-3. 왜 이렇게 갈랐나

- **폴더는 기능별**이다(확정 사항). `Core` 는 층 골격, `Hub` 는 꺼내 쓰는 길, `Events` 는 알리는 길,
  `Resource` 는 만들고 반납하는 길로 **역할이 겹치지 않는다.**
- **폴더 이름을 `Resources` 가 아니라 `Resource`(단수)로 쓴다.** `Resources` 는 Unity 특수 폴더라
  그 안의 것이 빌드에 통째로 들어간다. 이름만으로 사람이 헷갈릴 자리라 단수로 피한다.
- **`~Util` 베이스는 없다.** `static class` 는 상속이 안 되고, 규칙이 곧 선언이라 뼈대로 줄 것이 없다 (2차 2장).
- **`~Manager` 베이스도 없다.** 2차 설계가 Manager 를 `IManager` + 필요한 `IProcess` **인터페이스 조합**으로 못 박았다.
  베이스를 주면 안 쓰는 빈 함수가 다시 붙는다.
- **인터페이스 3개를 `IProcess.cs` 한 장에 넣었다.** 컨벤션 2-2 는 **중첩 클래스** 금지이고 파일당 타입 하나가 아니다.
  한 줄짜리 형제 인터페이스 셋은 같이 봐야 뜻이 통한다.
- **`Officina.Hubs` 는 복수다.** `Hub` 단수로 하면 `InGameHub` 같은 타입 이름과 부딪혀 보인다.

### 1-4. 1차·2차 설계에서 어긋난 것 하나를 맞췄다

1차 5장은 `interface IServiceProcess { void Process(float) }` 였고, 2차 1장은 `IProcess` 를 만들었다.
**뒤에 정한 2차를 따라 `IProcess` 하나로 합친다** — 같은 뜻의 인터페이스가 둘이면 `GameRunner` 가 둘을 다 봐야 한다.
`IServiceProcess` 는 만들지 않는다. (1차 5장 결론 「시작할 때 이걸 단 Service 는 0개」는 그대로다.)

### 1-5. 샘플은 3장까지

**넣는다.** 다만 **베이스만 봐서는 알 수 없는 것**으로 한정한다.

| 넣는다 | 왜 |
| --- | --- |
| `SampleMaster` | **등록 순서가 곧 실행 순서**라는 규칙은 Master 파일을 봐야 보인다 (2차 1장) |
| `SampleManager` | `Init` 에서 `Hub.Get` 금지 → `PostInit` 에서 캐싱, 구독은 `PostInit`·해제는 `Dispose` 라는 짝 |
| `InGameHub` | 씬 Hub 하나를 새로 만드는 데 복붙할 5줄 |

| 안 넣는다 | 왜 |
| --- | --- |
| `SampleObject` · `SampleAgent` · `SampleUtil` | 베이스 클래스와 컨벤션 문서로 충분하다. 샘플이 늘면 게임이 지울 것도 늘어난다 |
| 샘플 이벤트 struct | `readonly struct` 한 줄은 예제가 필요 없다 |

**세 장 모두 첫 줄에 `// 본보기다. 자기 Master 를 만들고 이 폴더를 지운다.` 를 적는다.**
주석 규칙(최대 2줄)에 들어가고, 지워도 다른 곳이 안 깨진다(`Officina.Sample` 을 참조하는 파일이 없다).

## 2. asmdef 2장

### 2-1. `_Project/Scripts/Officina.Runtime.asmdef`

| 칸 | 값 | 까닭 |
| --- | --- | --- |
| `name` | `Officina.Runtime` | 다른 asmdef 가 이 이름으로 참조한다 (조사 3-2) |
| `rootNamespace` | `Officina` | 새 스크립트를 만들 때 Unity 가 이 값을 쓴다. 게임 프로젝트는 지금 비어 있어 아무도 강제하지 않는다 (조사 3-2) |
| `references` | `[]` | 뼈대는 `UnityEngine` 만 쓴다. 엔진 어셈블리는 참조를 안 적어도 붙는다. **필요 없는 참조를 미리 적지 않는다** |
| `includePlatforms` · `excludePlatforms` | `[]` · `[]` | 전 플랫폼 |
| `autoReferenced` | `true` | `Assembly-CSharp`(게임의 기존 느슨한 스크립트)가 참조를 안 적고도 뼈대를 쓸 수 있다. 처음엔 이쪽이 덜 막힌다 |
| `allowUnsafeCode` · `overrideReferences` · `noEngineReferences` | `false` · `false` · `false` | 기본값. `noEngineReferences` 가 참이면 `MonoBehaviour` 를 못 쓴다 |
| `defineConstraints` · `versionDefines` · `precompiledReferences` | `[]` | 쓸 것이 없다 |

### 2-2. `_Project/Scripts/Editor/Officina.Editor.asmdef`

| 칸 | 값 | 까닭 |
| --- | --- | --- |
| `name` | `Officina.Editor` | 관행 |
| `rootNamespace` | `Officina.EditorTools` | **`Officina.Editor` 로 쓰면 안 된다** — `UnityEditor.Editor` 클래스와 이름이 부딪혀 `Editor` 한 낱말이 모호해진다. 어셈블리 이름만 `.Editor` 로 두고 네임스페이스는 `EditorTools` 로 가른다 |
| `references` | `["Officina.Runtime"]` | **한 방향이다.** Editor → Runtime 만 있고 반대는 없다 |
| `includePlatforms` | `["Editor"]` | 이것이 「에디터 전용」의 실제 뜻이다. 빌드에 안 들어간다 |
| `excludePlatforms` | `[]` | `includePlatforms` 가 있으면 비운다 |
| `autoReferenced` | `true` | 에디터 쪽 느슨한 스크립트가 쓸 수 있게 |

### 2-3. Runtime 이 Editor 를 참조하지 않는 방향

Editor asmdef 가 `includePlatforms: ["Editor"]` 라 **런타임 빌드에 아예 없다.** Runtime 이 참조하면 빌드가 깨진다.
그래서 방향은 기술적으로 강제된다 — 문서 규칙이 아니라 컴파일이 잡는다.

**GUID 참조를 쓰지 않고 이름 참조를 쓴다.** 템플릿에 `.meta` 를 안 넣으므로(조사 3-4) GUID 를 알 수가 없다.
이름 참조는 `\bOfficina\.` 치환에 그대로 걸린다.

## 3. `Assets/Default.globalconfig` 1차 내용

### 3-1. 자리와 머리

`Assets/` 루트 **한 장**이다 (조사 1-1). asmdef 옆에 따로 두지 않는다 — 어셈블리가 둘뿐이라
두 장으로 갈라 두면 「어느 쪽이 먹나」를 사람이 매번 따져야 한다.

```
is_global = true
```

`global_level` 은 안 적는다. 겹치는 globalconfig 가 없어 우선순위를 정할 일이 없다.

### 3-2. 고른 진단 11종

**「컨벤션 문서가 사람에게 시킨 것 중 기계가 잡을 수 있는 것」만 골랐다.** 43종을 다 적으면 규칙이 묻힌다.

| ID | 무엇 | 세기 | 왜 이 세기 |
| --- | --- | --- | --- |
| UNT0007 | Unity 객체에 `??` | **error** | 컨벤션 2-5 가 사람에게 시킨 것이고, Unity 객체에선 **틀린 답을 낸다**(파괴된 객체가 null 이 아니다) |
| UNT0008 | Unity 객체에 `?.` | **error** | 위와 같은 이유. 2-5 의 `?.` 항목 |
| UNT0010 | `MonoBehaviour` 를 `new` | **error** | 2차 6장 — `~Object` 는 `ResourceService.Rent` 로만 만든다 |
| UNT0011 | `ScriptableObject` 를 `new` | **error** | AGENTS 10 — SO 는 수치 통이고 아무 데서나 만드는 물건이 아니다 |
| UNT0004 | `Update` 에서 `Time.fixedDeltaTime` | **error** | 1차 3장 — dt 를 만드는 자리는 `GameRunner` 한 곳뿐이다 |
| UNT0005 | `FixedUpdate` 에서 `Time.deltaTime` | **error** | 〃 |
| UNT0006 | 잘못된 메시지 시그니처 | **error** | 오타가 나면 **조용히 안 불린다.** 가장 비싼 침묵 |
| UNT0013 | 잘못된·군더더기 `SerializeField` | **error** | AGENTS 10 — 인스펙터 배선 금지. 직렬화 칸이 늘어나는 것을 입구에서 막는다 |
| UNT0002 | 비효율 태그 비교 | warning | 고치는 법이 하나뿐(`CompareTag`)이라 error 로 올려도 되지만, 게임이 남의 코드를 옮겨 올 때 막히면 시끄럽다 |
| UNT0003 | 제네릭 아닌 `GetComponent` | warning | 위와 같음 |
| UNT0001 | 빈 Unity 메시지 | warning | 껍데기를 먼저 만들어 두고 채우는 흐름을 error 로 막으면 일이 안 된다 |

적는 꼴은 `dotnet_diagnostic.UNT0007.severity = error` 다.

**억제기(USP0001~0023)는 아무것도 안 적는다.** 켜져 있는 것이 기본이고, 특히 `USP0023` 이
`IDE1006`(이름 규칙)이 `Start`/`Update` 를 물지 않게 막아 준다 (조사한 컨벤션 조사 3-2).

**이름 규칙(`dotnet_naming_rule`)은 1차에 안 넣는다.** 컨벤션 문서의 이름 규칙이 아직 안 정해졌고
(`Todo/코드와저장소.md` 3장), 반쯤 정한 규칙을 error 로 박으면 되돌리기가 비싸다.

### 3-3. 확인 안 된 것 — 검증 뒤 조정한다

- **`.globalconfig` 가 Unity 안에서 실제로 먹는지 확인하지 못했다.** IDE 패키지 소스로 「그렇게 쓰게 돼 있다」까지만 봤다 (조사 1-2·6장).
- **UNT 번호와 규칙의 짝**은 2차 자료(`[전언]`)다. **파일을 쓰기 전에 Microsoft.Unity.Analyzers 의 README 로 11개 번호를 한 번 대조한다.**
  틀린 번호를 적으면 그 줄이 조용히 무시된다 — 없는 진단 ID 를 적어도 오류가 안 난다.
- VS 설치가 감지되지 않으면 csproj 에 항목이 아예 안 들어간다 (조사 1-2 함정 1). **Unity 안 컴파일과 IDE 검사의 결과가 다를 수 있다.**
- 그래서 1차는 **11줄로 짧게** 두고, 검증(5장) 결과를 보고 세기를 옮기거나 줄을 더한다.

## 4. 설치 스크립트 설계

### 4-1. 이름과 껍데기

**`CodeTool/install.ps1`** 한 장이다. `Install-Template.ps1` 같은 동사-명사 꼴도 후보였지만,
**사람이 문서를 안 보고 저장소를 열었을 때 눈에 걸리는 이름**이 낫다고 봤다. README 에 한 줄로 적는다.

PowerShell 을 고른 까닭 : 개발 환경이 Windows + PowerShell 이라 **의존성이 0**이고,
CodeTool 은 지금 Go·Python 런타임이 필요 없는 문서 저장소다. 복사·정규식 치환에 빌드 단계를 붙일 값이 없다.
PowerShell 5.1 규칙(`&&`·`??`·삼항 없음, 파일은 UTF-8 BOM, 머리에 `Set-Location $PSScriptRoot`)을 따른다.

```powershell
install.ps1 -AssetsPath <게임 Unity 프로젝트의 Assets 경로> -Namespace <게임 네임스페이스> [-DryRun]
```

| 인자 | 뜻 | 검사 |
| --- | --- | --- |
| `-AssetsPath` | 목적지. **`Assets` 폴더 자체를 받는다** | 아래 4-2 |
| `-Namespace` | 치환할 이름 (예: `MyGame`) | `^[A-Za-z_][A-Za-z0-9_]*(\.[A-Za-z_][A-Za-z0-9_]*)*$` · 각 토막이 C# 예약어가 아닐 것 · `Officina` 자체는 거절(치환이 무의미하고 잔여 검사가 못 돈다) |
| `-DryRun` | 아무것도 안 쓰고 계획만 찍는다 | — |

**`-Force` 같은 우회 옵션을 만들지 않는다** (`security-invariants` 2번).

### 4-2. 절차

```
0) Set-StrictMode -Version Latest · $ErrorActionPreference = 'Stop'
1) 인자 검사
   - Namespace 정규식·예약어 검사               실패 → 종료 2
2) 목적지 검사
   - $dest = Resolve-Path -LiteralPath $AssetsPath   (링크까지 푼 실제 경로, 딱 한 번)
   - leaf 이름이 'Assets' 인가                   아니면 종료 2
   - (부모)/ProjectSettings/ProjectVersion.txt 가 파일로 있나   없으면 종료 2
   - git 미커밋 변경이 있으면 경고 한 줄만 찍고 계속 (막지 않는다 · 까닭 4-5)
3) 원본 훑기
   - $src = Resolve-Path Template            (한 번만 정규화)
   - 파일 목록 = 폴더를 직접 내려가며 모은다 (-Recurse 는 쓰지 않는다)
   - 항목이 재분석 지점(링크·정션)이면 건너뛴다. 폴더면 안으로 들어가지도 않는다
   - 파일이 0장이면 종료 2 (「왜 0장인지」 한 줄)
4) 목적지 경로 계산 + 경로 감옥
   - rel = 원본 상대경로 · 이름 치환 적용 (asmdef 파일 이름)
   - rel 에 '..' · ':' · 절대경로 꼴이 있으면 종료 3
   - 목적지 = $dest\rel → 가장 가까운 있는 조상 폴더를 정규화해 $dest 접두인지 대소문자 접어 비교  아니면 종료 3
   - 그 조상부터 $dest 까지 **모든 조상**이 재분석 지점이 아닌지 본다 (중간 하나라도 정션이면 종료 3)
   - 목적지가 이미 폴더면 종료 3
5) 계획표 만들기 (처리 = 만듦 / 덮음 / 건너뜀)  ← 4-3 표대로
6) -DryRun 이면 계획표를 찍고 종료 0
7) 쓰기 (파일 하나마다)
   - 원본 내용을 읽는다 (UTF-8, BOM·CRLF 는 읽을 때 흡수)
   - 메모리에서 치환한다 (4-4)
   - 줄바꿈을 LF 로 통일한다
   - 덮는 파일이면 먼저 프로젝트 루트(Assets 의 부모)에 <이름>.bak-yyyyMMdd-HHmmss 로 보관한다
   - 같은 폴더의 tmp 파일에 쓰고 Move-Item 으로 제자리 바꿈 (반쯤 쓰인 파일을 안 남긴다)
   - 덮은 파일은 다시 읽어 쓴 내용과 대조한다        다르면 종료 6
8) 치환 잔여 검사 — 이번에 쓴 파일만
   - \bOfficina\. 가 0개인가
   - .asmdef 안에 "Officina" (따옴표 포함) 가 0개인가
   - 0개가 아니면 고치지도 지우지도 않고 파일·줄 번호를 세어 알린 뒤 종료 5
9) 보고 — 계획표 + 합계 + 「사용자가 할 일」 세 줄
```

`security-invariants` 항목별로 이렇게 받았다.

| 항목 | 이 스크립트에서 |
| --- | --- |
| 1. 경로 감옥 | 뿌리 **둘**(원본 `Template`, 목적지 `Assets`). 각각 한 번만 정규화 → 접두 비교 → 보통 파일 확인. 링크 항목은 건너뜀 |
| 2. 비밀정보 | 해당 없음(밖에서 오는 글이 없다). 대신 **`-Force` 를 안 만든다** |
| 3. 주입 중화 | 해당 없음 (AI 에게 먹이지 않는다) |
| 4. 원자 쓰기 | tmp → rename. 락은 없다 — **동시 실행이 위험한 공유 상태가 없다**(목적지가 인자로 갈린다) |
| 5. 안 지운다 | **삭제는 자기가 방금 만든 tmp 파일을 Move-Item 실패 때 지우는 한 곳뿐이다.** 덮는 파일은 백업이 먼저. 잔여 검사에 걸린 파일은 세어서 알리기만 한다 |
| 6. 남의 설정 | `.globalconfig` 는 백업 → 쓰기 → 다시 읽어 대조. 다른 파일은 애초에 안 덮는다 |
| 7. 읽기·인코딩 | 읽을 때 BOM·CRLF 흡수, 쓸 때 LF. **모르는 인자는 즉시 실패**(`CmdletBinding` 기본값). 오류를 삼키는 자리는 **0곳** |
| 8. 종료 코드 | 4-6 표 |
| 9. 그밖 | 시험은 스크래치패드의 **가짜 프로젝트**에 돌린다. 게임 프로젝트에 대고 돌리지 않는다 |

### 4-3. 덮어쓰기 규칙

| 대상 | 이미 있으면 | 왜 |
| --- | --- | --- |
| `Default.globalconfig` | **덮는다** (백업 먼저 — 백업은 `Assets/` 가 아니라 프로젝트 루트에 `Default.globalconfig.bak-<stamp>` 로 둔다) | 진단 목록은 CodeTool 이 정본이다. 세기를 고쳐도 게임 코드가 안 날아간다 |
| `.cs` | **건너뜀** | 게임이 고친 뼈대가 날아가는 것이 가장 비싼 사고다 (조사 4-2 나안) |
| `.asmdef` | **건너뜀** | 게임이 참조를 더해 뒀을 수 있다. 존재 검사는 **치환된 파일 이름**으로 한다 |
| `.meta` | **템플릿에 없다** | 넣으면 GUID 가 여러 프로젝트에 퍼지고, 덮으면 프리팹 참조가 조용히 끊긴다 (조사 3-4). Unity 가 만들게 둔다 |

건너뛴 것은 목록에 **「건너뜀」** 으로 찍는다. **뼈대 개선이 게임에 자동으로 안 들어온다는 것이 이 규칙의 값이다** —
들어오게 하려면 사람이 diff 를 본다. 그 절차는 7장 안내 문서에 적는다.

### 4-4. 치환 규칙

| # | 어디에 | 정규식 | 바꿔 넣는 것 |
| --- | --- | --- | --- |
| ㉮ | **이번에 복사한 파일 전부**의 내용 | `\bOfficina\.` | `<Namespace>.` |
| ㉯ | **`.asmdef` 내용만** | `"Officina"` (따옴표 포함, 정확히) | `"<Namespace>"` |
| ㉰ | asmdef **파일 이름** | `^Officina\.` | `<Namespace>.` |

- ㉮ 는 `namespace Officina.Core` · `using Officina.Hubs` · asmdef 의 `"name": "Officina.Runtime"` ·
  `"references": ["Officina.Runtime"]` 을 한꺼번에 잡는다. 점이 안 붙은 낱말 「Officina」는 안 건드린다 (조사 3-1 절충안).
- ㉯ 가 따로 필요한 까닭 : Runtime asmdef 의 `"rootNamespace": "Officina"` 는 **점이 안 붙어** ㉮ 에 안 걸린다.
- **템플릿이 지켜야 할 것** : **복사되는 27장 안에 점 없는 낱말 「Officina」를 쓰지 않는다** (라이선스 머리글·주석 포함).
  그래야 8단계 잔여 검사가 오탐 없이 돈다. 이것은 뼈대를 쓸 때의 규칙이라 5장 검증에 넣는다.
- **치환은 4단계에서 만든 「이번에 복사한 파일 목록」에만 돈다.** 게임이 이미 쓴 코드는 읽지도 않는다 (조사 4-3).
- 치환은 **쓰기 전 메모리에서** 한다. 복사한 뒤 다시 열어 고치는 방식은 중간에 죽으면 반쯤 치환된 파일이 남는다.

### 4-5. 멈추는 조건과 안 멈추는 것

**멈춘다** : 네임스페이스 꼴 불량 · `Assets` 폴더가 아님 · `ProjectSettings/ProjectVersion.txt` 없음 ·
경로 탈출 · 목적지가 폴더 · 원본 0장 · 쓰기 실패 · 대조 실패 · 잔여 토큰 > 0.

**안 멈춘다** : **git 미커밋 변경.** 조사 4-2 는 멈추자고 했는데, 실복사가 **덮는 파일이 `.globalconfig` 한 장**이고
그것도 백업을 뜨므로 되돌리기가 git 없이도 된다. 대신 경고 한 줄을 맨 위에 찍는다.
(이 판단이 뒤집히면 `-RequireCleanGit` 같은 **추가 검사** 인자로 붙인다 — 우회 인자는 안 만든다.)

### 4-8. 시험

**1차는 손 시험 3판이다.** 스크래치패드에 **가짜 Unity 프로젝트**를 만든다
(`Assets/` 빈 폴더 + `ProjectSettings/ProjectVersion.txt` 한 줄). 게임 프로젝트에 대고 돌리지 않는다.

| 판 | 무엇 | 합격 |
| --- | --- | --- |
| 1 | `-DryRun` | 아무 파일도 안 생긴다. 계획표 27줄이 다 「만듦」 |
| 2 | 실복사 | 27장이 생기고 잔여 0. `Officina.` 가 파일 안에 0개, `MyGame.` 가 들어갔다. 줄바꿈이 LF |
| 3 | 다시 복사 | `.cs`·asmdef 가 전부 「건너뜀」, `.globalconfig` 만 「덮음」 + `.bak` 이 생긴다 |
| 4 | 잘못된 대상 | `Assets` 아닌 폴더 · `..` 섞은 경로 · 빈 네임스페이스 → 각각 종료 2·3·2 |

**Pester 는 2차로 미룬다.** 붙일 자리는 `CodeTool/Tests/Install.Tests.ps1` 이고,
옮길 가치가 있는 것은 **경로 감옥과 치환 잔여**뿐이다 — 이 둘은 조용히 틀리고 회귀가 비싸다.
복사 자체는 눈으로 보면 바로 안다.

| 소단계 | 분류 | 예상 | 범위 | 누가 |

까닭 (`CLAUDE.md` 모델 규칙) :

- **1번은 갈라서 준다.** 총 1,170줄이라 **로컬 Qwen3.6 은 금지**(200줄 넘는 생성). 계획→첫 편집 하나는 Opus 가 직접 하고
  (`GameMaster.cs` · `ProcessList.cs` 둘이 절차적 맥락을 준다), 나머지는 **Flash-Next 에 파일 3~5장씩 묶어** 넘긴다.

- **3번은 Opus 다.** 경로 감옥·원자 쓰기·종료 코드가 섞인 판단 코드다. 조용히 틀리면 남의 저장소에 쓴다.
- **4번은 Qwen3.6 이다.** 정해진 4판을 돌려 출력을 표로 옮기는 단순 반복이다.

  (프로필 전환이 20~40초라 왔다갔다 하지 않는다).
- 판은 `localharness run --task <작업서> --runner <runner.txt>` 로 돌린다.

## 7. 빠진 것을 남기는 문서

복사 범위에서 뺀 것(폴더 트리 · `.gitignore` · `.gitattributes` · 서식 도구 · 애널라이저 DLL)은
**새 저장소를 팔 때 한 번 보는 것**이다. 스크립트가 아니라 안내 문서로 남긴다.

**`CodeTool/Docs/Guide/새저장소세우기.md` 한 장**을 제안한다. (쓰는 것은 다음 일이다)

| 목 | 내용 | 근거 |
| --- | --- | --- |
| 1. 폴더 트리 | `Assets/_Project/` 밑 `Art`·`Audio`·`Data`·`Prefabs`·`Scenes`·`Scripts`. 깊이 4단 넘기지 않기. `Assets/Settings/` 는 Unity 가 이미 만든다 | 조사 2-2 |
| 2. `.gitignore` | 뿌리 한 장 + Unity 폴더 이름 접두사. 손으로 붙인다 | 조사 2-3 |
| 3. `.gitattributes` | `* text=auto eol=lf` + LFS 범위. **`*.png` 를 넣을지는 아직 안 정했다** | 조사 2-4 |
| 4. 서식 도구 | CSharpier 대 `dotnet format`. 설정 파일 자리. **안 정했다** | 조사 1-5 · 7장 3번 |
| 5. 애널라이저 DLL | `RoslynAnalyzer` 라벨 · 플랫폼 전부 끄기 · `.meta` 를 같이 넣기 · `*.dll` 이 LFS 에 걸리는 함정 | 조사 1-4 |
| 6. 뼈대를 나중에 갱신하는 법 | `install.ps1` 은 `.cs` 를 안 덮는다 → CodeTool 의 `Template/` 과 diff 를 손으로 본다 | 4-3 |

**문서를 하나로 묶은 까닭** : 이 여섯은 **「새 게임 저장소를 처음 팔 때 한 번」** 이라는 같은 시점에 필요하다.
갈라 놓으면 그때 여섯 장을 찾아 읽어야 한다. 규칙 문서는 짧게 쓰고 상세는 조사 문서 경로로 가리킨다.
