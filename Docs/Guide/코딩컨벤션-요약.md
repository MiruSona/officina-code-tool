> 서식은 CSharpier, 함정은 애널라이저가 잡는다.

## SOLID

- **순수 C#** (전투·인벤토리·상태·데이터) : 전부 적용.
- **MonoBehaviour** : 컴포넌트 조합이 기본. 억지로 인터페이스 끼우지 않음.

## 규칙

### 2-1. partial 은 되도록 쓰지 않는다
한 클래스가 여러 파일에 흩어지면 보기 어렵다. 자동 생성 코드만 허용.

### 2-2. 내부(중첩) 클래스 금지
```csharp
// 나쁨 : private class Slot {} 를 클래스 안에 둔다
// 좋음 : public class InventorySlot {} 로 파일을 나눈다
```

### 2-3. 3년차가 바로 읽도록
똑똑한 한 줄보다 평범한 세 줄. 기계가 못 잡아 리뷰로 본다.

### 2-4. 들여쓰기 깊이 권장 3단계
강제는 아님. 3단계 넘으면 함수로 뺄 신호. 조건 뒤집어 일찍 빠져나온다.
```csharp
// 4단계 — 나쁨
if (a != null && a.IsAlive) foreach (var x in a.Items)
    if (x.Count > 0) Use(x);

// 일찍 빠져나옴 — 좋음
if (a == null) return;
if (!a.IsAlive) return;
foreach (var x in a.Items) { if (x.Count <= 0) continue; Use(x); }
```

### 2-5. `? :` `??` `?.` 되도록 쓰지 않는다
읽는 사람이 멈춘다. `if` 로 풀어쓴다.

### 2-6. 주석에 역사 쓰지 않음
git 이 기억한다. 최대 2줄(3줄까지), 이유보다 요약. 코드로 아는 내용은 안 씀.
순서 표·계획처럼 길어질 것은 **설계 문서에 두고 주석에는 경로만** 적는다.
```csharp
// 나쁨 : "2026-08-19 김OO 추가. 리스트에서 딕셔너리로 바꿈."
// 좋음 : "아이디로 자주 찾아서 딕셔너리로 둔다."
```

### 2-7. `if` 안이 2줄 이상이면 중괄호 필수
```csharp
if (dead) { return; } // 괜찮음
if (dead) { Cleanup(); return; } // 반드시 중괄호
```

### 2-8. 2중첩부터 한 줄이어도 중괄호 필수
```csharp
// 나쁨
foreach (var x in items)
    if (x.Ok) Use(x);

// 좋음
foreach (var x in items)
{
    if (x.Ok) { Use(x); }
}
```

### 2-9. 두 번 이상 반복되는 코드가 아니면 함수로 빼지 않는다
한 번만 쓰는 걸 함수로 빼면 정의 찾아 왔다 갔다 한다. 그 자리에 둔다.

## 우선순위

**2-9 vs 2-4 → 2-9 가 이긴다.**
깊이가 깊다고 무조건 함수로 빼지 말고, **early return(일찍 빠져나오기) 으로 푼다.**
이중 루프처럼 early return·continue 로도 못 풀면 **깊이 4를 그대로 둔다.** 2-4 는 권장이다.
